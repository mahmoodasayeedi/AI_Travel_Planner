# AI Travel Advisor ✈️ (Vercel version)

An AI-powered travel planner. Chat with the advisor, answer a few follow-up questions, and get a complete day-by-day itinerary with travel tips and an estimated budget. Built with a React frontend and a FastAPI backend, and deployed on Vercel.

## Features

- **Conversational planning:** the advisor greets you, asks about destination, duration, interests, budget and preferences, and asks for clarification when something is missing or contradictory.
- **Structured itineraries:** the final plan is returned as JSON and shown as a trip header, a ticket-style card for each day, travel tips and a budget breakdown chart.
- **Weather forecast:** 7-day forecast for any city from the Open-Meteo API.
- **Currency converter:** converts between EUR, USD, GBP, INR and CHF using Frankfurter reference rates.
- **Tool results in the chat:** the latest weather and currency results are sent to the model, so it can use them in answers and in the itinerary.
- **Conversation memory:** older messages are summarized automatically so long conversations still fit in the model's context.
- **Token usage and cost:** shows request count, input tokens and output tokens, plus an estimated cost once prices are configured.
- **AI destination image:** optional button on each itinerary that generates an illustration of the destination.
- **Saved conversation:** the chat survives a page refresh (stored in the browser). Generated images are not saved.
- **Responsive design:** works on desktop and mobile, with light and dark mode.

## How it works

Vercel runs short-lived serverless functions, so the backend keeps no memory between requests. The browser holds the conversation state and sends it with every chat request:

1. The user sends a message. The React app sends the full message list, the current summary, the number of already-summarized messages, and the latest weather and currency results to `POST /api/chat`.
2. The backend summarizes older messages if the history is too long, then calls the model with the system prompt and the prepared context.
3. The model replies with either a normal-text follow-up question or a complete itinerary as JSON.
4. The backend returns the reply, the updated summary and the token usage. The browser stores them and sends them back on the next request.
5. The frontend detects JSON itineraries and renders them as cards. Anything else is shown as a normal chat message.

## API routes

| Route           | Method | Purpose                                                                                    |
| --------------- | ------ | ------------------------------------------------------------------------------------------ |
| `/api/chat`     | POST   | Send the conversation, get the advisor's reply, updated summary and token usage            |
| `/api/weather`  | POST   | `{ "city": "Paris" }` returns a 7-day forecast                                             |
| `/api/currency` | POST   | `{ "amount": 100, "from": "EUR", "to": "CHF" }` returns the converted amount and rate date |
| `/api/image`    | POST   | `{ "destination", "itinerary_summary" }` returns a base64 JPEG illustration                |

Errors are always returned as `{ "error": "message" }`.

Input limits enforced by the backend: at most 100 messages per request, 2,000 characters per user message, 6,000 characters of summary, and a short list of supported currencies.

## Environment variables

| Variable             | Required | Description                                                                                                              |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| `OPENAI_API_KEY`     | Yes      | Your OpenAI API key. Keep it private.                                                                                    |
| `MODEL_NAME`         | No       | Text model name. Defaults to `gpt-6-luna`, the model used during development. Set it to a model your account can access. |
| `INPUT_PRICE_PER_M`  | No       | Price in USD per 1 million input tokens. Enables the cost display.                                                       |
| `OUTPUT_PRICE_PER_M` | No       | Price in USD per 1 million output tokens. Enables the cost display.                                                      |

Copy `.env.example` to `.env` for local use. Never commit the real `.env` file.

## Deploy to Vercel

1. Push the project to GitHub.
2. On [vercel.com](https://vercel.com), choose **Add New Project** and import the repository.
3. Leave the framework preset and build command empty. The frontend is already built into `public/`.
4. Open **Settings → Environment Variables** and add `OPENAI_API_KEY`. Add the optional variables if you want them.
5. Deploy. Vercel redeploys automatically on every push.

`vercel.json` raises the function timeout to 60 seconds, because image generation can take longer than the default limit.

## Run locally

### Backend

```bash
python -m venv .venv
# Windows PowerShell:  .\.venv\Scripts\Activate.ps1
# macOS/Linux:         source .venv/bin/activate
pip install -r requirements.txt
```

Set your API key in the terminal (the backend reads environment variables directly and does not load `.env` by itself):

```powershell
# Windows PowerShell
$env:OPENAI_API_KEY = "your_key_here"
```

```bash
# macOS/Linux
export OPENAI_API_KEY="your_key_here"
```

Start the server:

```bash
uvicorn app:app --port 3000
```

Open `http://localhost:3000`. The built frontend in `public/` is served from there.

You can also use the Vercel CLI (`npm i -g vercel`, then `vercel dev`), which uses your Vercel project's environment variables.

### Frontend (only if you edit the design)

```bash
cd frontend
npm install
npm run dev      # live development server, proxies /api to localhost:3000
npm run build    # builds into ../public
```

Run the backend on port 3000 while using `npm run dev`. After changing the frontend, run `npm run build` and commit the updated `public/` folder, because Vercel serves it as static files and does not build it. Delete old files in `public/assets/` if they are not replaced (the build does this automatically).

## Security notes

- The API key is only used on the server and is never sent to the browser.
- Request size, message count and field lengths are validated on the server.
- Model output is rendered as text by React, never as raw HTML, so a manipulated reply cannot inject scripts.
- Weather and currency results are sent to the model with a note that they are data, not instructions.
- The system prompt tells the model not to invent bookings, prices, weather or live transport information.

Known gaps for a public deployment:

- **No rate limiting or login.** Anyone with the URL can use your API credits. Add Vercel Firewall rate limiting (or a service such as Upstash) and set a monthly spending limit in your OpenAI dashboard.
- **Prompt injection is reduced, not eliminated.** A user can still try to steer the assistant away from travel topics. Keep the scope instructions in `prompt.py` clear and review conversations if you add more tools.

## Limitations

- AI-generated itineraries and budgets are estimates. Verify opening hours, prices and transport before booking.
- Exchange rates are reference rates, not bank or card rates.
- The cost estimate counts chat replies only. Summarization requests and image generation are not included.
- The conversation is stored in the browser, so it does not follow the user to another device.
- The image feature needs access to `gpt-image-1` on your OpenAI account.

## Troubleshooting

**`PYTHON_ENTRYPOINT_NOT_FOUND` on deploy.** `app.py` must be in the project root and define a variable named `app`. Delete any old `api/` folder left over from earlier versions.

**Every request returns 500.** Open the Vercel dashboard, go to your project, then **Logs**, and read the error for the failed request. Common causes: a missing file (all five `.py` files must sit next to `app.py`), a `requirements.txt` that does not list `fastapi`, `openai` and `requests`, or a missing `OPENAI_API_KEY`.

**"The AI request failed."** Check that `MODEL_NAME` is a model your account can use and that your OpenAI account has billing or credit available.

**Blank page after deploying.** The `public/` folder must contain `index.html` and an `assets/` folder from `npm run build`. Rebuild and commit it.

**Image generation fails.** Check that your account has access to the image model, and that the request finishes within the 60-second function limit.

**Weather says "Location not found".** Try the city name on its own, for example "Lisbon" instead of "Lisbon, Portugal".
